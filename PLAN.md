# go-ssh-ui — Masaüstü SSH İstemcisi Planı

## Bağlam

`go-ssh` (aynı üst dizinde kardeş repo, `/Users/buraktanriverdi/git/ssh/go-ssh`) host seçimi için tam ekran bir TUI, düzenleme için `--edit` ile açılan yerel bir web arayüzü sunan Go tabanlı bir SSH host yöneticisi. Bu repo (`go-ssh-ui`) onun masaüstü uygulaması sürümü.

İstenen özellikler: UI üzerinden host/şifre yönetimi, sekmeli çoklu terminal, çoklu jump-host üzerinden bile çalışan WinSCP benzeri sürükle-bırak dosya yöneticisi, sekmelere toplu komut gönderme, gerçek `ssh` kullanımını "kayıt ederek" host+şifre otomatik oluşturma (eşleşen şifre varsa yeniden kullanma), global kısayolla terminal penceresini öne getirme, macOS "liquid glass" saydamlığıyla uyumlu sade/hızlı bir arayüz. "Core" (config şeması, şifre deposu kriptografisi, jump-host mantığı, scripted-login kavramı) go-ssh ile aynı ruhta kalır ve aynı `~/.go-ssh/` dizinini paylaşır.

Aşağıdaki mimari, go-ssh kaynak kodunun (`config/config.go`, `password/password.go`, `ssh/ssh.go`, `web/`) incelenmesi ve güncel Wails v3 / Go SSH kütüphane araştırmasına dayanıyor.

## Mimari Kararlar

1. **Masaüstü kabuğu: Wails v3** (Go backend + native WebView, Electron gibi Chromium gömmüyor). v2, Tauri, Fyne/Gio ve Electron+Go-sidecar değerlendirildi; v3 kazandı çünkü tam olarak ihtiyaç duyulan şeyleri **birinci sınıf, üçüncü parti bağımlılık gerektirmeden** sağlıyor:
   - macOS 15+ için native **Liquid Glass** efekti (eski sürümlerde `NSVisualEffectView`'a düşüyor) — repo içinde `examples/liquid-glass` örneği mevcut → özellik 7.
   - Gerçek çoklu pencere API'si (`Application`/`Window`).
   - Native **SystemTray** API.
   - Native **`app.GlobalShortcut`** (Register/Unregister/GetAll) — üçüncü parti hotkey kütüphanesi gerekmiyor → özellik 6.
   - Native **dosya sürükle-bırak girişi** (`EnableFileDrop`/`OnFileDrop`, gerçek dosya yolları döndürüyor).
   - Risk: v3 henüz **beta** (sık point-release), masaüstü API yüzeyi "stabil" olarak nitelendiriliyor ama 3.0 GA öncesi küçük kırılmalar olabilir. Versiyon pinlenecek.

2. **SSH motoru: iki motorlu (Faz 2'de uygulandı, gerçekleşen mimari orijinal tek-motor planından sapıyor — burada güncellendi)**. `internal/sshengine` tek bir `Session` arayüzü arkasında iki motor barındırıyor:
   - **subprocess motoru (varsayılan)**: sistemin gerçek `ssh` binary'sini `github.com/creack/pty` ile shell'ler — tıpkı go-ssh CLI'nin yaptığı gibi. `Host.Command`/`Commands` alanı dolu olan (yani GUI'nin yapılandırılmış formundan hiç geçmemiş) **her host** bu motoru kullanır — bugünkü `~/.go-ssh` içindeki hostların tamamı bu kategoride. go-ssh'nin `ssh` paketindeki `ParseCommands`/`EnsureSSHAutoAcceptHostKeys` yardımcıları birebir yeniden kullanılıyor, böylece SEND/SENDPASS/WAIT/EXPECT/INTERACT otomasyonu, jump-host zincirleri, dzdo/sudo escalation, `~/.ssh/config`, ssh-agent, ProxyCommand — hepsi CLI'deki gibi çalışıyor, çünkü gerçekten aynı `ssh` binary'si çalıştırılıyor.
   - **native motor (`golang.org/x/crypto/ssh`)**: sadece `Host.HostAddr` dolu olan (GUI'nin "Basit" formundan kaydedilmiş) yapılandırılmış hostlar için. Jump-host zinciri programatik kurulur: `hop1Client.Dial("tcp", hop2Addr)` → `ssh.NewClientConn` + `ssh.NewClient` ile hop2 için gerçek bir `*ssh.Client` elde edilir, zincir boyunca tekrarlanır (standart "SSH-over-SSH" deseni); aynı hosta açılan birden fazla sekme bu zinciri ref-count'lu paylaşır. Terminal: `session.RequestPty("xterm-256color", ...)` + `session.Shell()` + xterm.js. Resize: `session.WindowChange(rows, cols)`. Keepalive **manuel** (`keepalive@openssh.com` global request ticker'ı) — `ServerAliveInterval` ücretsiz gelmiyor. `~/.ssh/known_hosts` uyumluluğu `golang.org/x/crypto/ssh/knownhosts` + TOFU onay dialogu için `github.com/skeema/knownhosts`; `ssh-agent` desteği `golang.org/x/crypto/ssh/agent`; 2FA/keyboard-interactive ve TOFU/passphrase soruları için Go↔JS senkron "prompt broker" (`internal/sshengine/prompt.go`) kullanılıyor.
   - Neden iki motor: bugünkü gerçek `~/.go-ssh` konfigürasyonundaki hostların tamamı legacy `commands:` + SENDPASS/EXPECT/dzdo betiklemesi kullanıyor — bunu native bir Go SSH bağlantısıyla (özellikle ara escalation adımlarıyla) birebir yeniden üretmek pratik değil. subprocess motoru gün 1'den itibaren mevcut hostların tamamıyla çalışmayı garanti ediyor; native motor ileride GUI'den oluşturulan yapılandırılmış hostlar için çoklu-sekme bağlantı paylaşımı ve (aşağıda güncellenen) SCP dosya transferi temelini sağlıyor.

3. **Frontend: Vite + TypeScript + Svelte**, terminal render için **xterm.js** (`@xterm/xterm` + `@xterm/addon-fit` + `@xterm/addon-webgl`) — sektör standardı, değişmiyor. Svelte gerekçesi bundle boyutu değil (Wails içeriği yerel gömülü assetlerden servis ediyor, ağ üzerinden indirme yok) — sekme listesi/bağlantı rozetleri/dosya ağacı gibi çok sayıda küçük canlı-güncellenen UI parçası için ince taneli reaktiviteden gelen düşük glue-code avantajı.

4. **Global kısayol + tray: Wails v3'ün native `app.GlobalShortcut` + `SystemTray` API'leri** — `golang.design/x/hotkey` gibi üçüncü parti kütüphane **kullanılmayacak** (framework'ün kendi event-loop'uyla çakışma riski var). macOS'ta arkaplanda dock ikonsuz çalışması için `Info.plist`'te `LSUIElement`/accessory-app ayarı. Dağıtım için code signing + notarization (`wails3 setup signing`) gerekiyor — Apple Developer hesabı gerektirir, kullanıcıya ayrı not olarak düşülecek.

5. **Dosya yöneticisi (WinSCP benzeri, çoklu jump-host destekli) — SFTP değil, SCP/SSH tabanlı** *(kullanıcı tercihiyle güncellendi — `pkg/sftp` protokolü değil, gerçek `scp`/`ssh` ile çalışan bir dosya yöneticisi isteniyor; Faz 4'te uygulanırken tasarım tek protokole sadeleşti, aşağıda güncel hali var)*:
   - **Aktarım — tek protokol, iki transport**: `internal/scpfs` klasik SCP tel protokolünü (kontrol satırları `C0644 <boyut> <ad>\n`/`D...`/`T...`, her mesajdan sonra tek byte'lık ACK/NAK) **kendimiz** uyguluyoruz, ama gerçek `scp` binary'sini shell'lemek yerine uzak uçta gerçek `scp -f <path>` (indirme, kaynak modu) / `scp -t <path>` (yükleme, hedef modu) komutunu çalıştırıp protokolün **istemci tarafını** konuşuyoruz — yani hâlâ gerçek `scp` kullanılıyor (uzak taraf), sadece yerel taraf `pkg/sftp` yerine bizim ~150 satırlık protokol kodumuz. Bu protokol koduna GİREN taraf (`io.Reader`+`io.Writer`) motora göre değişiyor: subprocess motorunda `ssh <host komutu> -- 'scp -f path'` alt sürecinin stdin/stdout'u; native motorda `session.Start("scp -f " + shellQuote(path))` ile açılan exec kanalı. Tek bir protokol implementasyonu iki motoru da kapsıyor.
   - **Dizin listeleme**: SCP protokolünün kendisi bir "dizin listele" komutu içermiyor. `RunRemoteCommand(host, "ls -la path")` adlı ortak bir yardımcı (yine iki transport'u da destekleyen) ile listeleniyor. Bu, sadece **tek adımlı, otomasyonsuz** bağlantısı olan hostlarda (native/yapılandırılmış hostlar, veya `command:` alanı düz bir `ssh ...` olan legacy hostlar) çalışıyor — etkileşimsiz bir `ssh host cmd` çağrısı escalation adımlarını (dzdo/SENDPASS/EXPECT) atlayacağından, `commands:` (çok adımlı) kullanan hostlarda **v1'de dosya yöneticisi desteklenmiyor** (net bir "bu host için önce bir terminal sekmesi açman gerekiyor" mesajı gösteriliyor) — bugünkü gerçek hostların çoğu bu kategoride; escalate edilmiş bir sekmeyi paylaşan gerçek destek sonraki bir iterasyona bırakıldı.
   - Finder → uygulama sürükleme (upload) `EnableFileDrop`/`OnFileDrop` ile native çalışır. **Uygulama → Finder sürükleme (native OS drag-out) Wails'te bugün desteklenmiyor** (WebKit/`WKWebView` kısıtı) — v1 için düşülen çözüm: "İndir + Finder'da göster" butonu.
   - İki farklı **remote** host arasında dosya taşıma, iki protokol oturumunu (kaynakta `scp -f`, hedefte `scp -t`) aynı anda sürüp aradaki byte akışını yerel süreç üzerinden köprülemekle yapılıyor — `scp -3` bayrağının yaptığının bizim protokol kodumuzla eşdeğeri.
   - **Bilinen tradeoff**: klasik SCP protokolü SFTP gibi byte-offset tabanlı yeniden-başlatılabilir bir aktarım desteklemiyor (yarıda kesilen transfer baştan başlar); ilerleme çubuğu, `C` kontrol satırındaki toplam boyuta karşı o ana kadar okunan/yazılan byte sayısını izleyerek hesaplanıyor (bunun için stderr ayrıştırmaya gerek yok, protokolün kendisi zaten boyutu veriyor).

6. **Config/şifre deposu paylaşımı**: `go-ssh`'nin `config` ve `password` paketleri (bubbletea/pty/web'e bağımlı değil, sadece `yaml.v3` + `pbkdf2`/`term`) **kopyalanmayacak** — `go-ssh-ui/go.mod` içinde `require go-ssh v0.0.0-00010101000000-000000000000` + `replace go-ssh => ../go-ssh` ile doğrudan import edilecek. Böylece iki uygulama **aynı `~/.go-ssh/config.yaml` + `conf.d/` + `passwords.enc`** dosyalarını birebir aynı kodla okur/yazar — sıfır kod tekrarı, sıfır format sapması riski. `go-ssh`'de hiçbir değişiklik gerekmiyor. Sadece `PasswordStore` CRUD API'si kullanılacak; `PromptMasterPassword` (terminal-only, `syscall.Stdin` kullanıyor) GUI'de kullanılmayacak — GUI kendi login ekranını web UI'daki gibi kuracak.

## Config Şeması Genişletmesi

`config.Host`/`config.Category` struct'larına **eklemeli, opsiyonel** alanlar: `ID` (uuid, jump-host referansları ve sekme/bağlantı anahtarlama için stabil kimlik — mevcut host'lara GUI'de ilk düzenlemede tembelce atanır), yapılandırılmış bağlantı alanları (`HostAddr`, `Port`, `User`, `AuthMethod`, `IdentityFile`, `PasswordID`, `JumpVia []string` — ID referansı). `yaml.v3`, `config.go`'da `KnownFields(true)` çağrılmadığı için bilinmeyen alanları sessizce yok sayıyor → **eski CLI, GUI'nin eklediği yeni alanları görmezden gelip sorunsuz çalışmaya devam eder**, geriye dönük uyumluluk için ekstra iş gerekmiyor. Eski `Command`/`Commands` string alanları korunur ("gelişmiş/manuel mod" olarak host formunda sunulacak, mevcut karmaşık `commands:` betiklerinin tam uyumluluğu için). Bu değişiklikler `go-ssh/config/config.go`'ya değil, `go-ssh-ui` içindeki `internal/configx` paketine (struct'ları saran/genişleten yardımcılar) yazılacak — go-ssh'nin kendi struct'larını değiştirmek gerekirse (örn. `Host`'a yeni alan eklemek), bu **go-ssh reposunda küçük, izole bir PR** olarak ayrı yapılacak ve CLI derlemesini/davranışını etkilemeyecek şekilde tasarlanacak (sadece yeni opsiyonel struct alanları).

  frontend/                  # Vite + TS + Svelte
    src/views/                # HostTree+HostForm, PasswordManager, TerminalTabs, FileManager, BroadcastBar, Settings

## Faz Planı

- **Faz 0 — İskelet**: `wails3 init` ile proje kurulumu, `go.mod` `replace` bağlantısı, `go-ssh/config`+`password` importunun bağımsız derlendiğinin doğrulanması (bubbletea/pty gelmediğinden emin ol), liquid-glass pencere + "hello world" Svelte sayfası (bind edilmiş bir Go metoduyla config okuma).
- **Faz 1 — Host & Şifre Yönetimi UI**: Ağaç CRUD (kategori/host), `conf.d` hedef dosya seçici, master-password unlock ekranı (`password.PasswordStore` üzerinden), host formu (yapılandırılmış alanlar + "gelişmiş mod"da ham `command`/`commands`), ID ataması. go-ssh'nin `SaveCategoryToFile`/`SaveHostToFile`/`RemoveCategoryFromFile`/`RemoveHostFromFile` yardımcıları doğrudan yeniden kullanılır.
- **Faz 1.5 — Native macOS Görünüm Geçişi** *(kullanıcı geri bildirimiyle eklendi — Faz 1 UI'si fonksiyonel ama "native Mac uygulaması" gibi durmuyor)*: Mevcut ad-hoc grid/buton düzeni yerine gerçek bir macOS "source list" sidebar (Finder/Mail/Ayarlar tarzı: ince, seçili satır sistem mavisi vurgusu, ikon+etiket hizası), üstte native görünümlü bir toolbar (trafik ışığı boşluğuyla hizalı, `InvisibleTitleBarHeight` ile uyumlu), emoji yerine SF Symbols hissi veren tutarlı bir ikon seti, sistem tipografi ölçekleri/ağırlıkları (başlık/gövde/altyazı hiyerarşisi), dialog'lar yerine mümkün olduğunca inline/sheet-tarzı düzenleme, hover/seçim durumlarında macOS'e özgü ince geçişler. Bu geçiş Faz 3'te terminal sekmeleri eklenmeden **önce** yapılmalı, aksi halde yeni sekme UI'si de aynı düzeltmeyi ikinci kez gerektirir. Kapsam: `App.svelte` kabuğu, `CategoryTree`/liste satırları, form dialog'ları; `glass.css` içindeki tipografi/renk/spacing tokenları yeniden kalibre edilecek.
- **Faz 2 — SSH Motoru Çekirdeği** *(tamamlandı)*: `internal/sshengine` iki motorla — subprocess (varsayılan, gerçek `ssh` binary + pty, go-ssh/ssh'nin ParseCommands/EnsureSSHAutoAcceptHostKeys'i yeniden kullanır) ve native (`golang.org/x/crypto/ssh`, sadece yapılandırılmış hostlar için, jump zinciri dahil). `RequestPty`+`Shell`, Go→JS event akışıyla (`terminal:output`/`terminal:connected`/`terminal:closed`) xterm.js'e çıktı, JS→Go bind edilmiş metodla girdi, `WindowChange`/`pty.Setsize` ile resize, native motorda keepalive ticker + keyboard-interactive/2FA dialog + knownhosts TOFU onay dialogu (`terminal:prompt` + senkron broker). `TerminalPane.svelte` tek seferde bir terminali tam ekran açıyor; sekmeler Faz 3'te.
- **Faz 3 — Sekmeler + Toplu Komut** *(tamamlandı)*: `App.svelte` gerçek bir sekme kabuğuna taşındı — pinned/kapatılamayan "Başlangıç" sekmesi (Hostlar/Şifreler içeriği) + host bağlanınca açılan yeni terminal sekmeleri; her `TerminalPane` bağlandıktan sonra sekmeler arası geçişte **unmount olmadan** (sadece `display:none`) canlı kalıyor, böylece arka plandaki sekmeler de `terminal:output`'u almaya devam ediyor. Aynı hosta açılan sekmeler native motorda tek `ssh.Client`'ı zaten paylaşıyor (Faz 2'nin ref-count'lu `pooledClient`'ı); subprocess motorunda her sekme bağımsız bir `ssh` alt süreci. Toplu komut: backend'de ayrı bir `broadcast` paketi yok — frontend, seçili sekmelerin (checkbox/chip ile seçilen) `sessionId`'lerine mevcut `TerminalService.Write` metodunu paralel çağırarak fan-out yapıyor (`Promise.all`), yeni bir Go API'sine gerek kalmadı. Terminal ekranında artık geri butonu yok; sekme çubuğundaki × ile kapatılıyor.
- **Faz 4 — SCP/SSH Tabanlı Dosya Yöneticisi** *(tamamlandı — SFTP değil, kullanıcı tercihiyle güncellendi, bkz. Mimari Kararlar §5)*: Backend (`internal/scpfs`: SCP tel protokolü + `ls -la` parse + Service; `FileService` Wails binding'i) gerçek `scp`/`ls -la` binary'lerine karşı test edildi. Frontend'de yeni `FilesPane.svelte` çift panel sunuyor — yerel pane (`ListLocal`/`HomeDir` ile gezinme, dosya seçip "Yükle") ve uzak pane (`List` ile `ls -la` tabanlı gezinme, breadcrumb, satır başı indir/yeniden adlandır/sil, araç çubuğunda yeni klasör). Remote path'ler her istek için baştan kurulan login-home'a-göreli segment dizisi olarak tutuluyor (RunRemoteCommand/OpenExec her seferinde tek seferlik bir ssh komutu olduğundan sunucu tarafında kalıcı bir cwd yok). Transfer ilerlemesi `file:progress`/`file:done` event'leriyle sağ-alt köşede canlı yüzde çubuğu olarak gösteriliyor. Finder'dan sürükle-bırak: `main.go`'da `win.OnWindowEvent(events.Common.WindowFilesDropped, ...)` ile `DropTargetDetails()`'daki dosya yollarını `files:dropped` event'i olarak frontend'e iletiyor; `FilesPane` kendi drop-zone `div`'ine benzersiz bir `id` vererek (aynı anda birden fazla dosya sekmesi mount'lu kalabildiği için, bkz. Faz 3'ün "sekmeler unmount olmadan gizlenir" deseni) hangi düşüşün kendisine ait olduğunu ayırt ediyor. `CanBrowse` false dönen hostlarda ("çok adımlı `commands:` kullanıyor") net bir Türkçe "önce terminal sekmesi aç" mesajı gösteriliyor. Host ağacındaki her host satırına `FolderOpen` ikonlu bir "Dosyalar" butonu eklendi (`CategoryTree.svelte`), `App.svelte`'de terminal sekmeleriyle aynı deseni izleyen paralel bir `fileTabs` dizisiyle sekme sistemine entegre edildi. Remote-remote kopyalama (`CopyRemoteToRemote`) backend'de hazır ama UI'da henüz bir giriş noktası yok — sonraki bir iterasyona bırakıldı.
- **Faz 5 — Kayıt Özelliği** *(tamamlandı, ilk sürüm gerçek kullanımda test edilip iki kez düzeltildi — bkz. altındaki not)*: Yeni `internal/record` paketi, `sshengine.Manager`'ın zaten tüm session tiplerini (subprocess/native/local) tek noktadan geçiren `Write`/`emitOutput`'una takılan bir `recorderSink` arayüzü üzerinden — üç motora da hiç dokunmadan. `Recorder` bir durum makinesi: `waitingCommand` (girişten satır satır yeniden kurulan komut, backspace/CSI-atlama dahil, `^ssh\s` eşleşince ilk adım olarak eklenip `watchingOutput`'a geçer) → `watchingOutput` (her yazılan satır — ikinci bir `ssh` hop'u, `dzdo`/`sudo` escalation, düz bir komut, ne olursa olsun — sırayla bir `StepExec` adımı olarak kaydedilir; ayrıca ANSI temizlenmiş çıktı kuyruğunda `password|passphrase|verification code|...:` tarzı prompt aranır) → `waitingSecret` (bir sonraki satır `StepSendPass` olarak yakalanır, `EventCaptured` ateşlenir) → tekrar `watchingOutput`. v1 kapsamı bilinçli olarak sadece yerel shell sekmelerinde (`TerminalService.ConnectLocal`) — plan metnindeki "gerçek `ssh` kullanımını kayıt ederek" ifadesiyle birebir örtüşüyor. `recordservice.go` (`RecordService.Start`/`Stop`, `record:event` ile canlı "prompt bekleniyor"/"yakalandı" durumu) sadece bir Snapshot (adım listesi) döndürür, hiçbir şeyi kendi başına kaydetmez. `TerminalPane.svelte`'de (sadece `local` sekmelerde) kırmızı noktalı bir "Kayıt" aç/kapa kontrolü + canlı durum metni; kapatınca en az bir adım algılandıysa `RecordReviewDialog.svelte` açılıyor — capture-then-confirm, asla sessiz kayıt yok: her `StepExec` satırı düzenlenebilir/silinebilir düz metin, her `StepSendPass` için mevcut şifre girişleriyle değer eşleştirmesi (dedup, `PasswordService.List`+`Reveal` ile) ve "yeni şifre" seçilirse düzenlenebilir id/açıklama/değer (reveal toggle'lı). Dialog kendi içinde bir kategori seçici (mevcut ağaçtan düzleştirilmiş) + `TargetFilePicker` barındırıyor ve onaylanınca doğrudan `PasswordService.Add` (yeni şifreler için) + `HostService.AddHost` çağırıp hostu gerçekten kaydediyor — `App.svelte`'deki `onHostSaved` callback'i Hostlar sekmesine geçiyor ki kullanıcı sonucu hemen görsün.
  - *Düzeltme 1 (gerçek kullanımda bulundu)*: ilk sürüm `watchingOutput`'ta prompt'a bağlı olmayan her satırı sessizce atıyordu — yani sadece ilk `ssh` komutu + parola adımları yakalanıyordu; kullanıcı bir hosta bağlanıp oradan **ikinci bir hosta** `ssh` ile atlayınca ve komut çalıştırınca bunlar kayba uğruyordu. Düzeltme: `watchingOutput`'taki her satır artık bir `StepExec` adımı olarak kaydediliyor (yukarıdaki tasarımda yansıtıldı).

## Kapsam Dışı (v1)

`ProxyCommand` string desteği, Windows/Linux paketleme (Wails cross-platform olsa da "liquid glass" isteği macOS-first; ileride genişletilebilir), native OS drag-out, otomatik güncelleme.

## Riskler

1. Wails v3 hâlâ beta — sürüm pinlenecek, 3.0 GA öncesi küçük API kırılmaları beklenmeli.
2. Finder'a native drag-out yok — v1'de "indir + göster" fallback'i zorunlu.
3. go-ssh `--edit` ile go-ssh-ui aynı anda çalışırsa dosya yazma çakışması (gerçek kilit yok) — mtime kontrolüyle uyarı.
4. `ProxyCommand`'lı mevcut `~/.ssh/config` girdileri otomatik çalışmaz.
5. Keepalive/idle bağlantı yönetimi elle kurulmalı, yoksa NAT arkasında sekmeler sessizce düşer.
6. Çok sayıda canlı sekme/WebGL terminal + çok sayıda SSH channel için kaynak ölçekleme stratejisi gerekir (arkaplan sekmelerde render duraklatma vb.), yoksa yüksek sekme sayısında uygulama ağırlaşır.
7. "Kayıt" özelliği sezgisel: login parolası ile sudo/2FA/banner promptlarını ayırt etmek kesin değildir → capture-then-confirm zorunlu, sessiz otomatik kayıt yok. Ayrıca bu mod aktifken tuş vuruşları geçici olarak bellekte tutulacağından (disk'e asla şifrelenmemiş yazılmadan), UI'de belirgin bir "kayıt aktif" göstergesi şart.
8. Paylaşılan şifre formatı PBKDF2-SHA256/100k iterasyon kullanıyor (günümüz OWASP önerisinin altında) — uyumluluğu bozacağından tek taraflı değiştirilmeyecek, ileride go-ssh tarafıyla birlikte ele alınabilir.
